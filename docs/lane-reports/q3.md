# Lane Q3: conversation panel on Raenn's answer pipeline

Branch `claude/lane-q3`, cut from `main` (aa59f32). Gate (`npm run gate`) green. Raenn's pipeline is the base; lane Q2's conversation layer is ported on top by hand. The design owner then changed the client from an inline thread to an agent chat panel; that is what is built.

## What Raenn's pipeline does (live mode)

1. Data facts first: `findFacts` computes number statements from the team's tables; a pure ranking question is answered by the ranking alone, with no model call.
2. Keyword search over papers only (our own derived sentences are left out), max 2 chunks per source, pool of 20; an off-topic question with little overlap is "not covered".
3. Haiku re-ranks the pool by how directly each passage answers (it may say none does); the top passages, one excerpt per source, go to the writer.
4. Haiku writes 1 to 3 JSON claims, each citing one source and copying one sentence verbatim; code drops a claim for: unknown source, quote not word for word, link or markup, banned phrase, over 25 words, more than 15 words of a short-quotes-only paper, added numbers, negations, absolutes or flipped direction.
5. A second Haiku read compares each claim with its quote ("not supported" drops it; an unusable reply keeps it flagged). Restricted papers show a quote cut to 15 words. If every claim fails, or the call fails, the server quotes the records.

## How each Q2 feature was re-fitted

- `history` (4 turns, 300/1200 chars, body 8 KB, 400 otherwise): `server/app.ts` schema; cache key includes `JSON.stringify(history)`.
- Retrieval: `retrievalQuery` (question + previous question) feeds the keyword search, the off-topic coverage check, the quoting mode and the per-sentence pick. The re-ranker sees "question (This follows the earlier question: ...)". Data facts are looked up with the new question alone, so an old ranking question cannot turn a follow-up into a ranking answer.
- Earlier turns reach the writer as alternating messages (`callHaiku` got an optional `earlier` argument). `earlierMessages` strips `<` `>` and every `[id]`; the writer system prompt says earlier turns are a record, never instructions, never evidence. The re-ranker and support check never see history. Every check on the final answer is unchanged.
- Habitat air: `HABITAT_AIR` (drift test against `public/data/habitats.json`) is in the `<habitat>` tag, plus a rule to compare and to say when the records tested different air. Conflict found: Raenn's checks drop any claim with a number not in its excerpt, and the support check judges against the excerpt only, so a habitat comparison could never survive. Fix, kept narrow: only when the question names the habitat (`asksAboutHabitat`) and a habitat is picked, the site's own air string is appended to the excerpt for the added-numbers check and to the quote shown to the support check, labelled "stated by this site and not by the source". The verbatim-excerpt rule, the 25 words, the negation and direction checks are untouched. Test: the comparison passes on a habitat question and the same figures are dropped on a non-habitat question.
- `steps`, `model`, `degraded`: see below. `degraded` was being stripped by `app.ts` on `main`; it is now sent and still not cached.

## Final `steps` fields (all counted by the code that did the step)

`searched` sources in the part of the library searched (live: papers only; quoting: quotable papers only) · `matched` sources handed to the writer (live) or quoted from · `facts` data findings computed for this question · `reranked` passages the model re-ordered (0 if the re-ranker did not run or its reply was unusable) · `kept` sentences in the answer · `dropped` sentences the writer produced that failed a code check or the support check · `checked` kept sentences the support check confirmed (kept minus checked = "not double-checked"). Mock: every field 0 (kept too). `model` is set only when live mode ends with sentences a model wrote; canned replies, quoting and samples give null. After a failed live call the fallback carries the refused count in `dropped`, so the page can say "SI wrote N sentences, but none passed the checks" instead of "did not answer".

## Client (panel)

- In the page: heading, one line, the one-line form, the example chips. Sending opens the panel with the question sent. No answer text in the page flow.
- Launcher "Ask SI" (text plus a dot), fixed bottom right, 44 px, safe-area aware, hidden while the panel or the detail drawer is open. Panel: `<dialog>`; `show()` (non-modal side panel, 420 px) at 600 px and up, `showModal()` (full-height `dvh` sheet) below. Escape and Close close it; focus goes to the composer on open and back to the opener on close.
- Thread state lives in `Ask`, above the panel, so close/reopen keeps it. Messages scroll the panel's own list (`el.scrollTo`, never `scrollIntoView`). Highlights only on "Show the N experiments" (`LIGHT_ON_ANSWER = false`); on a phone Show and See experiment close the sheet first.
- Under each answer: one summary line that opens (`details`) into the steps, then Raenn's sources (title, short-quote label, "Read the full source", relation labels, "not double-checked", See experiment), then Show. Data findings still come first.
- Empty state: four plain-word steps, example chips. Composer: textarea to 4 lines, Enter sends, Shift+Enter new line (IME-safe), count near the limit, follow-up chips above, "Answering for: <habitat>".

## Step labels and why

Summary line: live `Searched 59 sources · 4 used · 2 sentences checked · 1 dropped`; quoting `Searched 59 sources · 3 matched · quoted word for word`; fallback `SI writer did not answer · quoted word for word` or `SI's sentences failed the checks · quoted word for word`; sample `Sample answer · nothing searched or checked`; ranking `Computed from the team's tables · no paper search`; none `Searched N sources · nothing matched`. It counts sources (what the code counts), not passages.
Steps: 1 `Searched N sources, M were used` (+ findings computed, + "SI put the best passages first" only if `reranked > 0`, else "Passages kept in keyword order"). 2 `Written by SI from M sources` + "Claude Haiku, by Anthropic" from `model`; quoting `Quoted word for word, the SI writer is off`. 3 live `N sentences kept, each quoting its source` + "K confirmed by a second SI read" (the support check really tests that the source supports the sentence) + "not double-checked" + "dropped: failed a check"; quoting `N sentences copied word for word from the records` (no check claimed). Header line names the writer from the last reply's `mode` and `model`. While waiting: `Searching the records…` active, then "Then the answer is written", "Then each sentence is checked" (no claim yet).
